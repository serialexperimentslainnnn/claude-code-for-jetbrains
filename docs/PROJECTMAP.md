## What lives here

**Policy and procedure for humans**, plus the decision record. This is the one place in the repository that
is written to be read rather than looked up — and it is deliberately *not* where the code is described. What
the code is and where it lives belongs to the distributed map; what a person must *do* belongs here.

Three kinds live side by side and they are not interchangeable:

| Kind | Files | What it is for |
|---|---|---|
| **Procedure** | `RELEASE_PROCEDURE.md` · `RELEASE_CHECKLIST.md` · `BRANCHING.md` · `CI_SETUP.md` · `UI_TESTING.md` · `DRIFT_DETECTION.md` | What to do, in order, when doing a thing. |
| **Reference** | `BINARY_COMPAT.md` · `TELEMETRY.md` · `FAQ.md` · `TROUBLESHOOTING.md` | What is true, for someone who needs to know it. |
| **Decisions** | `adr/0001-release-process.md` · `adr/0002-threat-model.md` · `adr/0003-i18n-deferred.md` · `adr/0004-target-size-exception.md` (index: `adr/README.md`) | Why a thing is the way it is, dated and immutable. |

`trust-chain.asc` is the release trust chain: the public halves of the two hardware CAs and of the CI
signing key they certify, in one file because a user imports a chain or imports nothing. They are public
keys and belong in the repository; nothing secret does. It is written by `scripts/bootstrap-ci.sh` and
travels as an asset on every release, so an old release stays verifiable after the CI key is rotated.

## Conventions here

- **An ADR is a record, not a document to keep current.** It is dated, it states the decision and its
  consequences, and when the decision changes a *new* ADR supersedes it. Editing an old one to agree with the
  present destroys the only thing it was for.
- A recorded **deviation** stays recorded. `adr/0001-release-process.md` documents GitFlow and GPG-on-YubiKey as deviations
  deliberately, and one of its entries is a **correction** rather than a rule — that distinction is the
  document's value.
- **These documents are for people. Anything an agent looks up belongs in the map**, and anything about *how
  work is done here* belongs in `CLAUDE.md`.
- No development chronicle. Not here, not in the map, not in a code comment. A document states what is true
  now.
- No measurement that will move: store the command, not its output.

## Minefields here

- **`RELEASE_PROCEDURE.md` says to cut a tag by hand and that is stale and dangerous.** The release workflow
  derives and cuts the tag from the declared version when `main` is pushed; a hand-cut tag competes with it.
  **Never tag a release by hand.**
- **A merge to `main` with a bumped version publishes to the Marketplace unattended.** There is no reviewer
  gate; the environment scopes the credentials, it does not hold the release back. The human act is the merge.
- Branch protection is versioned in `.github/rulesets/`, but a ruleset references a check by the job's
  **display name** — renaming a job does not fail the gate, it silently stops applying it.
- The GitHub Environment's protection rules are a GitHub setting, not a file in this repository. A document
  here describing them is describing something it cannot enforce.
- **There is no backlog file here, and that is deliberate.** Pending work is tracked outside the repository;
  a document that accumulates finished work reads as a plan and is a chronicle.
