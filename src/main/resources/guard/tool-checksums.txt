# Verified checksums for the development and devops tooling the guard is allowed to skip reading.
#
# WHY THIS FILE EXISTS
# --------------------
# `DevToolScripts` exempts a build wrapper from the script analyser by NAME, and a name is chosen by whoever
# creates the file. This is the other half: where an official, publisher-signed checksum exists, the exemption is
# granted on IDENTITY instead — the file is what the publisher shipped, or it is not exempt.
#
# FORMAT
# ------
#   <sha256>  <artifact>  <version>
# Two spaces, `sha256sum`-compatible in the first two columns on purpose, so an entry can be checked by hand.
# Lines starting with `#` and blank lines are ignored. The artifact name is the file as it lands on disk, not a
# URL: the guard matches what it is about to skip, never where it came from.
#
# WHAT MAY GO IN
# --------------
# Only a checksum published by the tool's own vendor, fetched from the vendor's own domain. Never a hash computed
# from a file found on this machine — that would certify whatever is already installed, including whatever put it
# there, which is precisely the attack this file exists to refuse.
#
# WHAT CANNOT BE IN HERE, AND IS NOT A GAP
# ----------------------------------------
# - Distro-packaged binaries (`dnf`/`apt` builds of terraform, kubectl, docker...). They are rebuilt by the
#   distribution and their hashes do not match upstream by design. Those live in /usr/bin and the guard never
#   reads them anyway (`ScriptExecution.SYSTEM_BIN_DIRS`).
# - The `gradlew` / `mvnw` SHELL SCRIPTS. No vendor publishes a checksum for the generated script; what Gradle
#   signs is the `gradle-wrapper.jar` sitting beside it. A wrapper is therefore verified THROUGH ITS JAR.
