## What lives here

**The chat UI.** An inlined web app under a strict, hash-pinned CSP: no CDN, no external resource, nothing
fetched at runtime. It is the whole visible surface of a conversation — transcript, composer, cards,
dashboard and tab bar.

**There is no module system in the page.** Each file is its own hash-pinned `<script>`, and they meet through
`window.cc` / `window.CC`. That single fact produces most of the rules below.

The host half is [`../../kotlin/dev/lain/claudejb/ui/jcef/`](../../kotlin/dev/lain/claudejb/ui/jcef/PROJECTMAP.md):
it decides every payload and every state word, and the page paints what it is sent.

## Conventions here

- **Load order is a contract**, and it is declared in `JcefHost.appNames`, not by the directory listing. A
  file that reads another's namespace at load time must come after it: `app-core.js` first, then each
  family's shared namespace before its members, and the composer's, the dashboard's and the tab bar's spines
  last, because those build eagerly on load.
- **CSS cascade order is the same kind of contract**, declared in `JcefHost.CSS_PARTS`. The parts are
  concatenated in that order into one block; alphabetical is not the same order and would silently change
  which rule wins.
- **A layer goes in the work area — and it is `#work`'s `z-index: 0` that makes that mean anything.** A new
  floating surface is a sibling of `#conversation`, inside `#work`; never a `position: fixed` panel over
  `#app`. Inside that box the roles are settled and ordered — transcript, then a layer over it, then the
  dock, then the palette, then the find bar — each declared at its own rule and argued there. `#tabsbar` is
  outside `#work` and the dock is a row of its own, so nothing laid over the conversation can reach the tabs
  or the composer. **What holds all of that up is none of the five numbers: it is the `z-index: 0` on the
  positioned `#work`**, which is what opens the stacking context that scopes them. Take it away and they go
  back to competing at the root — where the body-mounted popups live, and where the three-digit values came
  from — and the containment comes apart **silently**: nothing looks wrong until somebody adds the next
  layer. That is why the contract asserts the stacking context *first* and the ordering only after, and why
  it asserts the ordering as relations between the roles rather than as digits.
- **The popups are mounted on `document.body` deliberately, and "it floats" is not the reason.** Escaping a
  clip is: a surface anchored inside `#tabsbar` cannot paint outside it, because that element hides its own
  overflow. The find bar floats too and belongs *inside* `#work`: mounted on the body it was positioned
  against the viewport, and in a narrow tool window it covered a focused chat tab outright, which is WCAG 2.2
  SC 2.4.11 (Focus Not Obscured). Escaping a clip is a reason to leave the work area. Nothing else is.
- **A module header's `Owns:` line is the row this map prints for it**, and it outranks the em-dash subject
  on the title line. That is the sentence to edit when a module's row reads wrong — not the table, which is
  generated.
- **Nothing is fetched.** Every dependency is vendored, every script and style is hash-pinned in the CSP.
  Adding a library means adding bytes to the artifact and a hash to the policy — there is no third option.
- **Links never navigate.** They route through the host, which decides whether the destination is openable.
- Model text is rendered through `marked` and then sanitised through `DOMPurify`. Never inject model text
  another way.
- A handler on an element that gets re-serialised through `innerHTML` **is lost**. Delegate from `document`.
- **The page paints the status word it is sent**; it does not derive one.
- Accessibility is part of the contract, not a later pass: the live region is declared in the static shell so
  the first write is announced, every suppressed outline has a `:focus-visible` replacement, and there is a
  `forced-colors` fallback.

## Minefields here

- **Never put a parenthesis in a comment inside `JcefHost.appNames` or `CSS_PARTS`.** `gen-projectmap.py`
  slices the declaration at the first `)` after `listOf(` without stripping comments, so one there truncates
  the list it reads and every module declared below it silently vanishes from the generated half of this map —
  load order, module row and registrations alike. `helpers/load.js` strips `//` lines before the same slice,
  so the tests keep loading the whole page while the map describes part of it, and nothing reconciles the two.
  It has happened; the fix is in the script, and until it lands the comment style is the guard.
- **A guard that skips a render must describe everything drawn, and nothing else.** Too little and the skip
  lies — a row the signature does not mention is drawn once and frozen, so an agent that finished keeps its
  running colour. Too much and the skip never fires, which at the dozens of pills the subtab row exists for
  is a full rebuild several times a second: that was the reported flicker. The rule for editing either file
  is one sentence — if the row starts drawing something it starts appearing in the signature, and if it stops
  drawing something it stops appearing there.
- **Do not "keep the DOM fresh while hidden."** The dashboard did exactly that and laid out a diagram nobody
  was looking at. Stash the payload; render on show.
- **Chromium does not move a horizontal scroller with a vertical wheel.** The gesture has to be translated,
  and focus has to be scrolled into view, or tabbing leaves focus off-screen.
- **Mouse events, not pointer events, deliberately**: `setPointerCapture` does not exist in jsdom, and this
  broke twice with no test noticing.
- **A full-window overlay covers whatever is laid under it.** The waiting screens are siblings of
  `#conversation` inside `#work`, not absolutely-positioned panels over the app: they share the transcript's
  grid cell, so they cover the transcript and can reach neither the tab bar nor the composer.
- **`#conversation`'s children belong to `cc.clear()`, which deletes them.** It runs on every switch between
  a chat, an agent and a task and on every session stop, and `#empty` is the one child it keeps. The waiting
  screens were put inside it and were wiped by the first clear — silently, because a render that cannot find
  its element just returns — so the screens only ever appeared in a chat tab that had not cleared yet. Put
  nothing in that element that has to outlive a transcript.
- **A control that overlaps a focusable element is a WCAG 2.2 failure** (Focus Not Obscured). Put it in the
  flow instead of keeping a padding in sync with the width of the words.
- **A bounded row needs both a bound and a cap**: without a width bound the row grows and its overflow is
  painted outside the tool window, where nothing can scroll to it; without a `max-width` on the label,
  `text-overflow` never triggers.
- **A delay is not a duration, and a waiting screen needs the delay.** A screen that must not appear on a fast
  start is held back by `animation-delay` plus `both` — `both` is what applies the 0% keyframe before the
  animation begins, so the element sits at opacity 0 through the grace. Lengthening the *duration* instead
  still paints frame one, which is the flash it was supposed to prevent.
- **`prefers-reduced-motion` must zero the delay too, not just the duration.** Zeroing only
  `animation-duration` leaves a timed reveal running under the preference: the element waits out its delay
  invisibly and then snaps in. The reset in `boot.css` sets `animation-delay` and `transition-delay` to `0s`
  as well, and being `!important` on a universal selector it reaches every part, including `dashboard.css`.
- **Stagger by CLASS, never by `:nth-child()`**, on anything whose siblings are toggled with `hidden`. Every
  `.auth-step` container exists at once with all but one hidden, so position counting hands the visible step
  the beat of its index in a list where exactly one is ever displayed.
- **`animation-delay` goes after the `animation` shorthand, always.** The shorthand resets it, so the reverse
  order silently drops the delay.
- Never write a round, an agent name or a development note into a module header. The header states what the
  module owns, and it is read verbatim into the generated map.
