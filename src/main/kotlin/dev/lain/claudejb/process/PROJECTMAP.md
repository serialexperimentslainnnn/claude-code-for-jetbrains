## What lives here

Everything between "there is a `claude` binary on this machine" and "a process is running and authenticated":
finding it, validating it, installing it, signing in, holding the credential, and spawning it with the right
environment.

The plugin **requires a preinstalled binary**. It does not vendor one, and it does not run Node.

## Conventions here

- **Credentials reach the binary by environment only.** Never argv, never a log, never the transcript, never
  any XML the plugin writes.
- **The plugin's auth identity is exclusively what it holds securely.** With nothing held, the state is
  logged-out by definition and no probe is run — probing would answer from the terminal CLI's own store, which
  is a separate identity the plugin does not own.
- **Nothing ever writes the credentials file back.** The vault takes custody and the file stays deleted; the
  credential travels as an environment variable that takes precedence over the binary's own store.
- Sign-in precedes the boot screen. Verifying auth needs no session, and launching one that is known to be
  unauthenticated buys a spawned process and a turn that fails for a reason already known at click time.
- `PluginContextPrompt` is **not a security control**. It carries no machine name, no environment value, no
  project content and no credential, and it describes no way around a rule. Its content is pinned by a test.

## Minefields here

- **`AuthCli` must be given the effective launch environment.** Run without it, a credential held in the safe
  reads as logged-out, and the plugin concludes the user is signed out while holding their credential.
- **Harvesting during a login destroys it.** `auth login` finishes by writing the very file the vault harvests
  and deletes; doing both at once breaks the browser leg of the flow and leaves code-paste as the only route
  that works.
- **The vault refuses to touch a real home from a test JVM**, and that guard is load-bearing: without it,
  running the integration suite harvests the developer's own credential into a throwaway test safe and deletes
  it. Invisible while the file was still written back; destructive the moment it was not.
- **`ClaudeLoginFlow` runs under pty4j, which REPLACES the child environment wholesale** rather than inheriting
  it. The parent environment has to be merged in explicitly or the spawned binary loses `PATH` and `HOME`.
- **The interactive TUI is in raw mode: only `\r` submits.** An `\n` hangs the card on "Verifying".
- **The binary opens the browser itself.** The host must not also open one — that produced two tabs.
- The OAuth-token identity is **reduced**: `auth status` then returns the route but no email and no plan. The
  email is still available, from the account object this package banked at sign-in.
- **`TerminalLauncher` is reflection over platform APIs that move.** Every lookup it makes has been removed or
  renamed at least once, and a missed lookup returns false rather than throwing — totally silent, nothing in
  the log. It is pinned against the build classpath by a contract test for exactly that reason.
