## What lives here

The host half of the browser: the embedded Chromium view, the two-way bridge, and **the JSON documents the
page is drawn from**. The page itself is
[`../../../../../../resources/jcef/`](../../../../../../resources/jcef/PROJECTMAP.md); this package decides what it
is told, and the page decides nothing.

The division is the design. **Every state word is decided host-side** and the page paints the word it is sent
— it never derives one. That is what stopped the tab bar saying `done` where the dashboard said `completed`
for the same task, each with its own CSS.

## How the package is grouped

The index below says what each file owns. What it cannot say is which of two jobs a file is doing, and that
is the only thing worth knowing before opening one:

- **The browser and the bridge** — `JcefHost` · `JcefBridge` · `LoopbackPageServer` · `RemoteDevNotice`.
  Getting the document into a browser and moving messages across the boundary. `JcefBridge` is deliberately
  free of IDE classes, so it unit-tests on a plain JVM.
- **The payloads** — every other file. They build the JSON documents the page is drawn from, and they are
  **null-safe by construction**: a card whose data is absent omits cleanly rather than drawing an empty one.
  `JcefSessionData` assembles the dashboard from `JcefAccountData` · `JcefCostData` · `JcefUsageData` ·
  `JcefWorkloadData` · `JcefPlanData` · `JcefGitData`, **one card each**; `JcefComposerOptions` and
  `JcefModelLabels` are shared by both model selectors so the two cannot disagree.

## Conventions here

- **Every builder is null-safe, and a card omits itself when its data is absent.** An empty panel is a worse
  answer than no panel; `null` here means "do not draw", never "draw nothing".
- **The status word is decided here.** Adding a fifth state means adding it to `JcefStatus` and to the CSS,
  in the same change — not inventing one at a call site.
- **`JcefBridge` stays pure.** An `import com.intellij.…` costs the package its cheap test layer, which is
  where the protocol between the two halves is actually pinned.
- Host→web updates are **coalesced per frame**, not sent per token. Streaming is the reason the UI is
  affordable at all.
- The load order of the page's scripts and the cascade order of its CSS are **read out of `JcefHost.kt`**, not
  globbed from the directory. Both are contracts, and a directory listing is alphabetical, which is not the
  same thing.

## Minefields here

- **`com.intellij.modules.jcef` is a HARD dependency and the `sinceBuild` floor exists because of it.** It is
  absent before 2025.3.1 and a bundled plugin from 262 on; an *optional* dependency that cannot be satisfied
  is skipped, which trades a clean refusal for a `NoClassDefFoundError` at the first chat. `verifyPlugin`
  cannot catch this — it resolves against the whole distribution, not the plugin's classloader — so the gate
  is a contract test.
- **Property and `init` declaration order.** A property declared below an `init` block that reaches it is null
  inside the constructor, and the nullable case is silent. The incident is next door in
  [`../`](../PROJECTMAP.md) (`JcefChatPanel`), and it took every chat with it.
- **The page route is a ladder, not a mode.** It falls through scheme → loopback → inline → notice, and each
  rung exists because the one above it fails in a real deployment. Do not collapse it into a boolean, and do
  not tie it to a platform API for detecting remote development.
- **A load that ENDED is not a page that ARRIVED.** Chromium reports its own error page as a finished load, so
  the end of a load says nothing on its own; the verdict needs the network failure *and* the HTTP status, and
  a status of `0` is a non-HTTP load, not a broken one. This is not cosmetic: everything the page owes is
  queued until it arrives, so calling a failed load a success **drains that queue into a page that cannot run
  it** and the next rung comes up with nothing left to draw.
- **The loopback token is one-shot and must not be spent by a rejected request.** A 404 answers with no body,
  before the token is compared: a rejection that consumes the token turns a stray probe into a dead chat, and
  a rejection with a body is a fingerprint of what is being served.
- **Nothing that leaves the host may carry the token** — not the notice page, not a log line, not an error.
- The dashboard must not render while hidden. Laying out a diagram and measuring its SVG for a panel nobody
  is looking at costs a frame several times a turn; stash the payload and draw on show.
