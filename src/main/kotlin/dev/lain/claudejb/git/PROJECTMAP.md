# Map of `git/`

> Part of the distributed map. **Root: [`../../../../../../../PROJECTMAP.md`](../../../../../../../PROJECTMAP.md)**
> — repository-wide commands, invariants and the index of every other directory map live there.

## What lives here

**Reading the repository's Git state, and nothing else.** There is no write path in this package and a
contract test fails the build if one appears — and that contract scans **this package only**. Everything that
*changes* the repository lives one layer up in [`../ui/`](../ui/PROJECTMAP.md), where the plugin almost always
asks the agent to run the command, or invokes the IDE's own action. **The exception is real and worth naming
here rather than leaving it to be inferred:** `ui/GitIntegration` spawns exactly one command itself,
`git init -b main`, with fixed argv and no user input reaching it. It is the one command with nothing to
decide, and it is what makes the card-gated path reachable at all on a project with no repository.

Git4Idea is an **optional** dependency, unlike JCEF. That is why `GitGateway` exists: it is the only file in
the repository that names a `git4idea` type, so an IDE without the plugin degrades to "no Git surface"
instead of a `NoClassDefFoundError` at the first click.

## Conventions here

- **Read-only, enforced.** `GitReadOnlyContractTest` fails the build on a write path in this package. Adding
  one is not a judgement call.
- **No `git4idea` type crosses this package's boundary.** A public signature returning a platform VCS type
  drags the optional dependency into every caller's classloader.
- Git entries in the UI are **absent, not greyed**, when there is no repository. A disabled menu item that
  explains nothing is worse than no menu item.
- **No Git UI is built here.** Where the IDE already has a window for something, we hand off to it.
- **A query that spawns a process refuses the EDT** rather than hopping off it: `recentCommits` and
  `branchTopology` return their empty answer and log which caller asked. A thread jump would buy the answer at the
  price of delivering it after the caller returned.
- **Unknown is not zero.** The ahead/behind counts are nullable because `0` reads as *in sync*, which is the one
  thing a failed `git rev-list` cannot tell us.

## Minefields here

- **`GitCommit.getAffectedPaths()` is internal API.** The Marketplace has already blocked a release of this
  plugin over an internal API, so this is a publication risk and not a lint. Paths come from `changes`, whose
  `afterRevision ?: beforeRevision` also keeps a deleted file in the list.
- **Both overloads of `SimpleListCellRenderer.create(…)` are marked for removal at 262.** Subclass the
  renderer; do not go through the factory.
- One *experimental* platform usage remains (`VcsChangesLazilyParsedDetails.getChanges()`), deliberately not
  a verifier failure level: experimental means "may change", not "will be removed".
- The optional dependency is declared in its own descriptor (`claude-git.xml`). A class from this package
  referenced from the main descriptor's code path would load unconditionally and defeat the whole
  arrangement.
