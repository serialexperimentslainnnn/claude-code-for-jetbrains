## What lives here

Showing the user a change before it happens, and undoing one after it has. **Diffs are the one part of the UI
that is deliberately not JCEF**: they are the IDE's own `DiffManager`, in the editor area, because reproducing
a diff viewer in a web view would be worse than the one the IDE already has.

The pivotal fact this package is built around: **the binary writes the file, not the IDE.** So a diff shown
before approval is a *reconstruction* of what the tool is about to do, and the snapshot taken beforehand is
the only record of what the file used to be.

## Conventions here

- **Diffs open in the editor area, never in a window or a modal.** Approval is an inline card in the chat, not
  a dialog.
- A diff opened for review must **not steal keyboard focus** — the user is still typing in the composer.
- The proposed side of a review diff is **editable**: the user may tweak it, and accepting writes what they
  see, not what the model proposed. When the input is re-encoded, the file path is never altered.
- Auto-writes are confined to the project root, and `isWithinRoot` is symlink-safe. That is the **write** gate
  and it is stricter than the gate for merely opening a file.
- A zero-hunk acceptance is a denial, not an empty write.

## Minefields here

- **The snapshot can go stale between the card appearing and the user accepting.** Reconstructing from a
  cached snapshot without re-reading disk is how a stale write clobbers a file the user edited in the
  meantime. Re-read, and fall back to a full accept when the file has diverged.
- **Computing hunks on a large file blocks the EDT.** There is a size ceiling for that reason; above it, a
  full accept still works and only the per-hunk view is skipped.
- **`isWithinRoot` is a security boundary, not a convenience check.** Symlink escapes are the case it exists
  for, and its tests cover them. The looser gate used for *opening* a file (project or `$HOME`) must not be
  confused with this one.
- The per-edit Restore lives on the **transcript card**, not in a panel. A second door onto it was built once
  and deleted; the panel it lived in also covered the tab bar the chat's own browser draws.
