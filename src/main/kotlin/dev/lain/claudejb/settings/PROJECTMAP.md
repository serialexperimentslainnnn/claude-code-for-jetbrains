## What lives here

Persistence, and what is derived from it. Settings are **global, not per-project**, and they live as one
`@Serializable` document in the IDE **PasswordSafe** — not in `.idea/`, because `envVars` is where an API key
or a credentialed proxy URL ends up, and that was a file people commit.

The UI for these settings is not here: it is the `Settings*Section.kt` files in
[`../ui/`](../ui/PROJECTMAP.md), behind the `SettingsSection` interface. **That glob matches one file more
than there are sections** — `SettingsSection.kt` is the interface, not a section, so counting the glob is
counting the seam as if it were a page.

## Conventions here

- **Every mutation goes through `ClaudeSettings.update {}`.** A bare `state.x = y` compiles, changes the field
  in memory, and silently does not survive a restart. Three "Always allow" mutators were doing exactly that.
- `update {}` writes off the EDT, on a serial queue. The Settings form's own save is the one place that goes
  through the direct path, because the form has already collected the whole document.
- Credentials are **slots, not fields**: the API key lives in its own provider slot, not in the settings
  document, so the Settings page and the sign-in card are two doors onto one credential.
- `CREDENTIALS_JSON` is file-shaped and deliberately **not** in the environment overlay.
- Legacy adoption is one-shot and the old file is deleted **only after the safe accepts the copy**.

## Minefields here

- **A failed READ is not an empty configuration.** A single bad read at startup, treated as "no settings",
  becomes a permanent overwrite on the next save. `readFailed` refuses the next save for that reason. This is
  not hypothetical: a keyring sync error lost a configuration on a real machine, and `set` reports failure to
  nobody.
- **The safe can fail silently.** Anything that assumes a write succeeded is assuming too much.
- The launch environment is where a secret would leak if one ever reached argv or a log. Changes to
  `SettingsLaunchEnv` are security changes.
- Environment variable names must be compared **case-insensitively** when stripping one: a hand-typed
  `Claude_Code_Oauth_Token` in Settings otherwise survives a strip and becomes the stale value that a renewal
  was replacing.
