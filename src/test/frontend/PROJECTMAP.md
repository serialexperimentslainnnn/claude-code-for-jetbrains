## What lives here

The tests for the web app, run under **vitest + jsdom**. They load the **real** inlined modules from
[`../../main/resources/jcef/`](../../main/resources/jcef/PROJECTMAP.md) — vendored libraries first, then
`app-core.js`, then the module under test — into a jsdom shell, and drive the public `window.cc` / `CC`
surface. Nothing is mocked that ships.

Everything here is a **devDependency**. Not one byte of this reaches the plugin artifact, and CI asserts that.

`helpers/load.js` builds the shell **by extracting it from the real `shell.html`**, never by hand-copying it.
A hand-copied shell had already drifted, which is the worst failure mode a harness has: it does not fail, it
quietly tests something else.

## Conventions here

- **Load the real module, in the real order.** A test that stubs a sibling namespace is testing the stub.
- **Contract tests come in both directions.** `css-contract.test.js` checks that every class the JS writes
  has a rule; `bridge-contract.test.js` checks the two halves of the host↔web protocol agree. One direction
  alone leaves the other free to rot.
- **A source scan reads code, never the prose around it** — `helpers/source.js`, one copy for all three
  scanning gates. This repository documents by quoting the code a comment is about, so every shape they look
  for appears in prose as often as in source; and the three read it in opposite directions, so the same
  paragraph invents a demand in two of them and withdraws one in the third.
- The CSS parts are read from the same declared list the host uses, so a part cannot go untested by being
  added to the directory and nowhere else.
- **DOM-identity assertions, not just content assertions**, where the point is that a render was *skipped*:
  the only way to prove a guard works is to show the node is the same node.
- Accessibility is a test subject here, not a review item.

## Minefields here

- **jsdom is not Chromium.** It has no `setPointerCapture`, no real layout, no scroll. Code written against
  pointer events broke twice with a green suite; mouse events are used deliberately for that reason.
- A green frontend suite says nothing about whether a module **runs** in the page. `asset-manifest.test.js`
  checks that every `app-*.js` and `css/*.css` on disk is in the host's declared list (and the reverse), but
  membership is not reachability: order is not checked, and a module that is served and never called is just
  as dead.
- On this machine node-24 needs `OPENSSL_CONF=/dev/null`. That is a local environment quirk and not needed on
  the clean CI image — do not encode it in the repository.
